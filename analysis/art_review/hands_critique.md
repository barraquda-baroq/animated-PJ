# hands.js 総作画監督チェック（独立レビュー）

対象：`pv/engine/lib/hands.js` / `pv/scenes/_dev_hands.js`（dev_hands_1〜10）
初回レンダリング（修正前）：`analysis/art_review/hands_review/r0/h1〜h10/`（still.cjs, t=0,2,4）
単体計測（修正前、ヘッドレスChromium・関数のみ・中央値）：手1つ 9ms / rim 11ms / handsTouch 33ms / handsInterlock 26ms（rim 30ms）/ handOnKeys 19ms / handOnFrets 25ms / armCast 17ms。初回呼び出しは 35〜56ms に跳ねる。

総評：**骨格（3D リグ＋IK＋奥行きソート）は良くできているが、絵としては「ベクタークリップアート」の段階で、劇場作品の手のアップには出せない。** 特に PV の要である「最終カットの恋人つなぎ」「弦を押さえる左手」「ギプス」は、シルエットで何をしているのか一目で読めない。担当者の自己評価は弱点を過小に見積もっている（下の A 級はどれも自己評価に挙がっていない）。

## A. 致命的（このままでは本編に使えない）

### A1. 最終カット `handsInterlock` が「恋人つなぎ」に読めない（dev_hands_5 / 6）
- 彼の指が太く短いソーセージ状に、カメラへ突き出すように見える。彼女の基節（指の付け根側）が彼の指の間から見えず、「交互に指が入っている」ジッパー状の構造が読めない。
- 彼女の中節・末節（分割パーツ B）が彼の指の下から**二重写しのように**はみ出している（指が2本ずつあるように見える）。
- 計算上の指の間隔：彼女の指幅18u に対して指の中心間隔が 20u しかなく、彼の指（20u）が入る隙間がない → 投影で重なり、交互構造が潰れている。
- 彼の親指（＝物語上いちばん大事な「傷のある左手の親指」）が既定アングルで完全に隠れている。最終話「右手と左手で互いの傷痕をなぞる」を描けない。
- rim 版（dev_hands_6）では分割点が暗い半円の「穴」に見え、爪が暗いキャップとして浮く。

### A2. `handOnFrets` が「コードを押さえる手」に見えない（dev_hands_3）
- 手のひらが巨大なミトンのようにネックの手前に出ており、指は2〜3個の塊しか見えない。人差し指は IK の目標（5フレット）に届いていない（デバッグ表示で確認）。
- 親指が「ネックの下から生えた5本目の指」に見える。
- ライブハウスの暗い背景に、昼光の明るいセル塗りの手がそのまま浮いている（光の不一致）。

### A3. `armCast` が抽象的な図形にしか見えない（dev_hands_7）
- スリングの袋がギプスの手前を覆い、ギプスはほぼ見えない。袋は「青いボトル形」、帯は「ただの長方形」で、腕を吊っている構造が読めない。
- 覗く指先は茶色の小さな粒（ぶどうの房）で、手に見えない。物語上「動かない右手」を見せるカットなのに指が読めない。

### A4. rim（逆光）スタイルの縁取りが逆光に見えない（dev_hands_1 右下, 6, 9）
- 光側の輪郭線が**暗いまま光の外側を一周している**ので、リムが「内側に引っ込んだオレンジの帯」に見える。逆光では光側の線は光に食われる（色トレス）べき。
- リム（白〜淡黄）の帯が細く、オレンジの透過帯の方が主張している。縮小すると「オレンジの縁取りシール」に見える。
- 爪が暗い塗り＋輪郭線のキャップとして指先に乗る。逆光で爪の形が見えるのは不自然。
- `handReach`（dev_hands_9）は **手のひらがカメラ側**。窓の光へ手を伸ばす人物の背後から撮るなら見えるのは手の甲（右手なら親指が左）。意味が「こちらへ手を差し出す」に変わってしまっている。

### A5. 手首の「茎状突起」が外にはみ出したイボに見える（ほぼ全カット）
- `m.styloid`（半径4.6の円）が手首の輪郭の外に飛び出し、輪郭線付きの小さな丸い突起になる（dev_hands_1 R back / dev_hands_4 彼の手首 / dev_hands_5 彼女の手首）。

## B. 重大（解剖・形の破綻、美しさの不足）

### B1. 指が「筒（ソーセージ）」に見える
- 指の太さ：彼女の基節の直径 18u（≈17mm）は実寸としては正しいが、アニメの「細く長いピアニストの指」の様式化としては太い。彼の指も骨ばっていない（均一な太さの筒）。
- 指先が丸い半球キャップで終わり、末節の先細り（爪側が平たく、腹側が丸い）がない。鍵盤カット（dev_hands_2）では指先が「こぶ」に見える。
- 関節のふくらみが左右対称のコブ（disc の半径を一律に拡大）。関節の出っ張りは背側に出るもので、側面の輪郭は滑らかに細くなるのが正しい。

### B2. 曲げた指の団子化・折り線の破片（dev_hands_10 左の薬指・小指、dev_hands_1「curl 0.5」）
- 屈曲時に追加する「角ばった関節」disc ＋関節 disc ＋指腹 disc ＋指先の血色（ピンクの丸）が重なり、手前に倒れた指が肉団子になる。
- 折り目の輪郭線（重なりの描き分け）が、短縮されたカプセルに対して**途切れた円弧**として描かれ、輪ゴムのような破片が出る。

### B3. 爪
- 手の甲側から見た爪が「白い長方形のシール」（親指）や「指先の白いキャップ」（人差し指・中指）になっている。白っぽすぎ、大きすぎ、先端の白い遊離縁の線が指の輪郭に乗っている。
- 先輩の爪は「短い」のが設定（本人が気にしている）。短さは伝わるが、白いキャップは「付け爪」に見える。

### B4. 縫合痕が「フランケンシュタイン」
- 梯子状の縫い目（両側に飛び出す tick）が濃く規則的で、手術直後の抜糸前に見える。物語の終盤（半袖の夏、互いの傷をなぞる）では**淡い桃色の盛り上がった線＋かすかな縫合点**であるべき。最終カットで観客が痛々しさだけを受け取ってしまう。

### B5. 袖口が「土管」（dev_hands_2）
- 袖が太さ一定の筒で、袖口を覗く角度だと穴の内側に腕が見え、手首が穴の縁から生えている（中心に入っていない）。紺の筒が画面右上へ一直線に伸びる。

### B6. ハンカチ・拳
- `handOffer` のハンカチが小さく厚い白い箱（角砂糖／カード）に見える。布の柔らかさ、垂れ、畳み目がない。手の向きも「差し出す」に見えにくい（真横から、指が水平）。
- `handFist` はブロック状。指の第2関節の段差がなく、親指が四角い板。

### B7. 鍵盤カットの演出（dev_hands_2）
- 既定カメラが「譜面台の向こうから奏者を見る」逆アングルで、鍵盤と手の関係を読み解くのに時間がかかる。打鍵した鍵の沈みがほとんど見えない。手の影が鍵盤に落ちていない（濃度 0.22 で背景に溶ける）。

### B8. 雨の窓 `handPress`
- 曇りのハローが手の輪郭全体に均一に付き、「光るオーラ」に見える。曇りは接地部（手のひら・指腹）の周りに出るもの。手も雨の青灰色の光に染まっていない。

## C. スタイルガイドとの不一致
- **線幅**：ガイドは 1.2〜2px（1080p）。現状は `lw*2` のストロークの外側半分＋影側の追加線で、scale 3.5 のアップでは実効 3〜4.5px。太くて「塗り絵」っぽい。→ 実効 1.4〜2.4px に収める。
- **光の色**：どのシーンでも昼光の同じ肌色（#f3d3bf）で塗られ、暗いライブハウス（dev_hands_3）、夜の拳（dev_hands_8）、雨の窓で手だけが浮く。ガイドの「シーン別の基調」に合わせて**環境光で肌・影・線を染める仕組み**がない。
- **rim の暗部**：`#3a2c36` は紫寄りで肌に見えにくい。ガイドは「暗い肌色＋縁の明るいリム」。

## E. 描画速度
- 単体関数は概ね目安内だが、**初回呼び出しで 35〜56ms**（バッファ確保・グラデーション生成）。二つの手のカットは中央値 26〜33ms、背景込みのフレームでは 45〜50ms と報告されている。
- 指の折り線判定 `overlaps()` が全セグメント対で毎回走り、`clipOut` の evenodd クリップを多用している。セグメント数が倍になる二つの手で効いている。

## 修正方針（優先順）
1. 共通の絵作り：指の太さ・先細り・関節の背側のふくらみ・爪・線幅・縫合痕・タコ・茎状突起を作り直す（全カットに効く）。
2. rim：光側の色トレス、リム帯の幅と明るさ、爪・分割点の処理、暗部の色。
3. 環境光 `ambient` オプション（肌・影・線をシーンの光で染める）を追加し、暗いシーンのショーケースに適用。
4. `handsInterlock` を「指の間隔を広げ、彼の指先が彼女の手の甲に乗る」形に組み直し、彼の親指が彼女の傷の上に来る既定ポーズにする。
5. `handOnFrets`：手の位置・カメラ・指の広がりを直し、指のアーチと押弦点、ネックの上から覗く親指が読める形に。
6. `armCast`：スリングを腕の下（奥）に回し、ギプス・指・帯の構造を読める形に作り直す。
7. 袖口・ハンカチ・拳・handReach（手の甲向き）・handPress（接地部の曇り）・鍵盤の既定カメラ。
8. 速度：初回コストと二つの手のカットを 40ms 以内に。

## 修正ログ（総作監が自分で修正。レンダリング：`hands_review/r1`〜`r3`、比較：`hands_review/before_after.jpg`、最終一覧：`hands_review/final_overview.jpg`）

### 1往復目（r1）— 共通の絵作りと読めないカットの作り直し
- **プロポーション**：指の軸を拳頭より細く（彼女 0.85倍・彼 0.9倍）、末節を先細りに（先端 0.84倍）。拳頭は手のひらの球で残すので「指の付け根の段差＝拳頭」が出る。母指球の球を追加（親指の付け根が凸に膨らむ）。
- **関節**：左右対称のコブを廃止。ふくらみは背側へずらした小さな円だけ、陰影のずらし量は隣の指節と揃える（団子状の塊が消えた）。強い屈曲時だけ角ばった背側の角。指先の血色 0.34→0.22、PIP の血色 0.14→0.07、曲げた関節のハイライト 0.6→0.32。
- **折り線**：同じ指で「手前の節が根元側」の重なりには輪郭を描かない（指を奥へ曲げた時の輪ゴム状の破片を除去）。
- **爪**：白いキャップ／白いシールを廃止。短い爪は先端の手前で止め、遊離縁の白線なし。地は肌と爪色の中間、光側半分を明るく、細いハイライト、線は細く半透明。rim/シルエットでは描かない。
- **線幅**：`lw = clamp(0.95+手の大きさ/700, 1.1, 2.1)`（光側の実効幅、旧 1.1〜4.4）。しわ・傷は別幅 `dw`。
- **縫合痕**：梯子状の縫い目 → 治癒後の「淡い桃色の盛り上がった線＋薄いハロー＋片側ずつのかすかな縫合点」。
- **タコ**：黄色い汚れ → 平たい淡黄の楕円＋薄茶の縁（近位側の弧）＋弦の溝2本（スタイルガイドの「薄い茶色の線」）。
- **茎状突起**：手首の輪郭の内側へ移動（イボが消えた）。短い前腕の端は2本の筒の丸2つ → 1つの丸い端。
- **環境光** `keyColor/fillColor/tint` を追加。
- **rim**：光側の暗線を「色トレス」に、リム→透過光→暗部の帯を再設計、暗部を暖色寄り `#3e2c33` に。
- **袖**：肘側へ広がる形。袖口を覗くアングルでは袖を手の奥へ回し、腕は袖口で切り、手前の縁（lip）と奥の暗がりで「腕が袖に入る」形に（土管の穴に手首が刺さる見た目を解消）。
- **handsInterlock を IK で作り直し**：相手の指先を手前の手の拳頭のくぼみに置き（ずらし量の計算ミス＝互い違いになっていなかった問題も修正）、相手の手を親指側へ半指ずらして**相手の親指が橈側の縁を越えて手の甲に乗る**ように。彼の傷のある親指が彼女の傷のある手の甲に乗る＝最終話の「互いの傷をなぞる」を1枚で描ける（`trace`）。
- **handOnFrets**：届かない指をなくす手の自動配置（反復）、既定カメラをボディ側の斜め上へ（指のアーチが読める）、既定コードを自然なフォームに。
- **armCast**：スリングを「腕を下から受ける袋（手前の布は腕の下半分だけ）＋両端から首へ向かう2本の帯（腕の奥）」に作り直し、指を拳頭の少し先から出す。
- **handOnKeys**：既定カメラを奏者の右・斜め上（`az 0.8, el 0.52`）へ。手・沈んだ鍵・譜面台の映り込みが同時に読める。
- **handOffer**：ハンカチを大きく柔らかい布に（丸い角・波打つ縁・折り目・垂れた角）、手のひらが見える既定アングル。**handPress**：曇りを接地部の周りだけに。**handReach**：既定を手の甲側に。
- ショーケース：rig sheet のラベルと手首の重なりを解消、各シーンに環境光・袖・自然なコードを指定。

### 2往復目（r2）— r1 を見て出た問題
- 環境光で影が濃い紫になり「黒い縁取り」に見えた → 影は key 光も 55% 受け、fill へは半分だけ寄せる（1影の段差を保つ）。
- 線が細すぎて明るい背景に溶けた → `lw` を少し太く（上の式）。
- 親指が指の手前を横切るのに、奥の指のハイライトが透けて見えた → 重なり判定を緩めて親指の節を塗り直す。
- タコ・縫合痕が明るい画面で読めない → 不透明度・縁の濃さを上げた（梯子には戻さない範囲）。
- handFist を作り直し：指を手のひらに巻き込み、親指は IK で人差し・中指の中節の上へ（旧版はトンネル状の穴が見えた／親指が手の甲に描かれた）。拳の正面アングルを用意。
- rim の透過光帯が細くなりすぎた → 幅を戻す。曲げた拳頭の白い点（4つの光の粒）を弱く。
- フレットの親指を `thumbOver` で出す試み → 既定カメラでは人差し指に隠れるため、既定は「ネック裏」に戻し、オプション扱いに。

### 3往復目（r3）— 速度と仕上げ
- **速度**：各アイテムの輪郭を `Path2D` にキャッシュし、影・リムのずらし塗りは `translate` で描画。rim の色トレスは「光と反対へずらした1本の線」に置き換え（クリップ不要）、rim では読めない細部（しわ・掌紋）を省略。逆光の恋人つなぎ 41ms → 27ms。
- フレットのショーケースを「Cフォーム＋小指のハンマリング」に（指が重なる不自然なフォームをやめた）、袖口を画面外へ。
- 全10シーン再レンダリング、PAGE ERRORS なし。`hands/` の公式画像と `overview.jpg` も最新に更新。

## 残る弱点（正直に）
- **handOnFrets** が最も弱い。指同士の衝突を解かないので交差するフォームは破綻する。親指を上辺に掛けるジミヘン型は既定カメラでは見えない。ネックが「浮いた板」で、ヘッドやボディとの接続はシーン側で隠す必要がある。
- 指は先細りカプセルの合成なので、超アップ（scale>4）では腱・骨の凹凸が足りず、線に手描きの強弱の揺らぎはない。
- 恋人つなぎの相手の親指の付け根に、ごく薄い円弧の継ぎ目が残る。
- ギプスは剛体の殻で、包帯のよれや汚れはない。スリング・ハンカチに布の揺れのシミュレーションはない。
- 明るい背景＋エンジンのブルームでは肌と背景のコントラストが落ちる。シーン側で背景の明度を一段落とすか `keyColor` で肌を少し沈めること。
